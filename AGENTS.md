# Project conventions

Summary of what `README.md` explains. If this file and the code disagree, the code wins. This is Astro 7 (Vite 8, Rust compiler, Zod 4): check the docs at https://docs.astro.build before using an API from memory. Collections live in `src/content.config.ts` with a `glob()` loader, entries have `id` (never a frontmatter `slug`), the router is `<ClientRouter />` from `astro:transitions`, and `output: 'hybrid'` no longer exists.

- **One Astro site, two languages, no CMS.** Routes: `/`, `/works/[slug]`, `/about`, `/writings` and `/writings/[slug]` in English, the same under `/es` in Spanish, plus one static bilingual `404` (`/404.html`, served by Vercel for every unknown path; no `es/404.astro`). The prefix of each language comes from `DEFAULT_LOCALE` through `src/lib/i18n-paths.ts`; never write `/es` or `/en` by hand. The 404 is the only page without `BaseLayout`: its view is a full document with its own head (`layers.css`, `themeInlineScript`, `<ClientRouter/>`, `startRouteTransitions()`), `noindex` and `data-page="404"`. Pages in `src/pages/` are thin: they pick the locale and render a view from `src/views/`. The only on-demand route is `src/pages/api/chat.ts` (`prerender = false`); everything else is static.
- **Languages**: `src/i18n/messages/es.ts` is the typed reference catalogue and `en.ts` `satisfies` it, so a missing key fails `npm run check`. No component writes visible text: everything comes from the messages or from the `works` and `writings` collections (product and proper names may live in `src/data/`). Anchors and slugs are not translated.
- **Content**: case studies are MDX in `src/content/works/{es,en}/<slug>.mdx` and articles in `src/content/writings/{es,en}/<slug>.mdx`, always in both languages; the locale and slug come from the entry id. Prev/next are computed from `order`, never stored. A case body uses only the components of `src/components/portfolio/case/index.ts` (contracts in its `types.ts`): the six fixed `CaseSection`s in order, each with its body first and its blocks (`data-case-block`) after; see README "Writing a case study". An article body uses Markdown plus the components of `src/components/portfolio/writing/index.ts` (README "Writing an article"). Drafts (`draft: true`) exist only in `astro dev`; `writingsForLocale` / `writingStaticPaths` in `src/lib/writings.ts` are the only places that decide it. Components used inside MDX read the locale from the URL, never from a prop.
- **Portfolio vs demos**: `src/components/portfolio/**` is the site itself. `src/demos/<project>/**` is UI of the reviewed apps, rendered live inside a case study. Demos never import from `src/components/portfolio`, `src/styles` or `src/i18n`; their styles are CSS Modules plus a `tokens.css` scoped to `.demo-root[data-demo="<project>"]` in `@layer demos`, and they only read `--d-*` tokens. `src/components/demo-frame/DemoFrame.astro` is the only seam between both worlds. MDX imports each demo statically (dynamic tags cannot hydrate).
- **Islands**: `.astro` by default. JavaScript for the global chrome (pill nav, theme toggle) is vanilla in a `<script>` with `src/lib/spring.ts`; React islands only where there is real state that does not load on every page (Blue panel, Aqua buttons, the /about toolkit folder, demos), hydrated with `client:idle` or `client:visible`, or mounted with `import()` from a vanilla script (the Blue panel). `motion/react` lives only inside those islands. An island mounted with `import()` that survives navigations imports its CSS from the `.astro` that renders its host: the `<ClientRouter/>` head swap drops the styles a dynamic import adds. A fixed element that must make room for the Blue panel only reads `var(--pf-blue-offset)`; the transition comes from the `@property` on `<html>`, never its own.
- **Motion**: every timing, easing and spring comes from `src/components/motion/presets.ts` or the CSS custom properties of the tokens; no magic numbers inside components. Page appear animations use the WAAPI engine with springs precomputed to `linear()` by `src/lib/spring-to-linear.ts`; they play once (`data-appear`). A reveal that plays in and out each time it crosses the viewport (the /about Experience) uses `data-reveal` and its own client script instead, with the end state in the CSS and the hidden state only under `html.js` without reduced motion. `prefers-reduced-motion: reduce` is always respected (opacity-only, nothing hidden, autonomous loops paused).
- **CSS**: cascade layers in this order: `reset, tokens, pf, demos`. Portfolio components style themselves in their `<style>` block inside `@layer pf`, strict BEM (`block__element`, modifier `_key_value`; a block takes the `pf-` prefix only when it is styled from `<style is:global>` or `portfolio.css`, e.g. `pf-stellar`, `pf-theme-toggle`, `pf-squircle`; scoped blocks go unprefixed), native nesting under the root selector, media queries inside the block, no `!important` (the only one is the instant theme switch of `portfolio.css`). The one set of global utility classes is the side-note hover API (`pf-note-hv-*`), read by `side-note-art/` and styled by `SideNote.astro`. Breakpoints: ≥1200, 810–1199.98, ≤809.98. Tokens are `--pf-*` in `src/styles/tokens.css`, with `[data-theme="dark"]` overrides. No Tailwind, no CSS-in-JS.
- **Forms**: inputs never have a `placeholder`; the label is enough.
- **Files**: components in PascalCase (`PillNav.astro`, `BluePanel.tsx`); everything else kebab-case. Named exports outside Astro/MDX files; no barrels except `src/components/portfolio/case/index.ts` and `src/components/portfolio/writing/index.ts`, which MDX imports (the writing barrel re-exports the case chat and side notes from their files, not from the case barrel). Imports with `@/...` and `@demos/...`.
- **Logic**: whatever can be tested without a browser goes to `src/lib/` as a pure function with a `*.test.ts` next to it.
- **Code language**: identifiers and comments in English; visible copy lives in the messages and MDX.
- **Debt**: what is found and not fixed goes to `IMPROVEMENTS.md` (area, priority, approach); mechanical tasks to `todos.md`. Both in English. Every important change is documented in the same commit (`README.md` for setup, scripts, content or routes; `AGENTS.md` if it IS a convention).
- **Reference material**: `docs/`, `recon/` and `scripts/recon/` hold the analysis of the reference design and stay out of git. `docs/decisiones.md` records Sebastian's decisions and wins over the rest of `docs/`.
- **Commits**: small, conventional, lowercase, in English (`feat:`, `fix:`, `style:`, `chore:`, `docs:`, `test:`), author Sebastian Luna, no co-author trailers.
- **Before calling something done**: `npm run check`, `npm run lint`, `npm test` and `npm run build` green. Layout and performance always against `npm run build && npm run preview`, never against `astro dev`; phones with real 390 px emulation. Do not leave dev or preview servers running.
